## Open

- **OTP / PIN / CVV rule: known limits.** English plus a Hinglish `OTP bata do` form only (no Devanagari or Kannada patterns, on purpose: an unchecked pattern should not force a verdict). A genuine delivery-OTP instruction ("share the OTP with the delivery partner") fires it. `text`, `message`, `confirm` and `enter` are left out of the verb list (real OTP SMS use them), so "confirm your OTP" is not caught. A negation more than 3 words from the verb, or split by anything other than one comma-delimited aside, is not recognised and the sentence counts as a request. (The comma-interrupted negation, "Do not, under any circumstances, share your OTP", was fixed on 2026-10-09 and is in `tests/tricky_inputs.py`.)
- **Brand / keyword check on free-hosting subdomains escalates harmless names.** `pineapple-recipes.netlify.app` (brand `apple`: brands of 5+ letters match as a substring), `amazon-fan-blog.github.io` and `my-support-group.vercel.app` all become Suspicious; `freelance-dev.pages.dev` and `riverbank-photos.pages.dev` correctly stay "Can't judge" (keywords of under 5 letters must be whole words). This is the specified behaviour (any brand or scam keyword escalates), so a personal site with such a name gets a false Suspicious. The lists are hand-written and not exhaustive (24 shorteners, 36 free-hosting domains): `kozow.com`, `ooguy.com` and `giize.com` appear in the OpenPhish misses of `reports/url_head.md` and look like free subdomain services, but that was not checked, so they are not listed.

What does reach train: 369 phishing rows (363 `000webhostapp.com`, 4 `glitch.me`, 2 `repl.co`) against 105 benign (99 `wordpress.com`, the only platform with real benign user sites in train, plus 6 others on `bitbucket.io`, `onrender.com`, `railway.app`, `fly.dev`, `ngrok-free.app`, mostly bare Tranco root domains). So the model has never seen a benign user site on the modern platforms and scores them from the generic shape of the hostname (which features carry it was not measured). The excluded benign rows are scored but never trained on: 27% of `blogspot.com` (400) and 81% of `weebly.com` (16) are flagged. Workaround in `src/app.py` only: free-hosting links get no model verdict ("Can't judge by domain - free hosting"); a brand or scam keyword in the subdomain raises them to Suspicious. The model and `reports/url_head.md` are unchanged. Fix: add benign platform-hosted URLs (and group the conflict rule by full host, or by platform, so those domains are not dropped wholesale), then check subdomain-only features or a free-hosting flag; re-measure on a held-out platform.
- **PII masks miss some UPI handles and dotless email addresses.** `pii.MASKS` only knows a fixed list of UPI suffixes (sbi, hdfc, icici, axis, paytm, ybl, ibl, upi, apl, okaxis, okhdfcbank, okicici, oksbi), and the email mask needs a dot in the domain. Handles like `@axisbank` and `@indus` (seen as `dunzo.payu@axisbank`, `olamoney.payu@indus`) and addresses like `x@localhost` stay in the text. 70 of 48,790 `messages.csv` rows contain such an `@handle` (counted, not printed): phishing_email 44, scam_ham_india 18, fake_job_postings 5, uci_sms_spam 3; train 47 / val 15 / test 8; none synthetic. The SMS sources (21 rows) are the likely UPI/payment IDs; the email and job-post hits are mostly mailing-list-style addresses (`@localhost`, `@python`, `@netscape`), which are not personal UPI IDs but are still unmasked. Fixing the masks changes those rows' text hashes, so it is a splits-v2 decision (delete or re-freeze `split_map.csv` deliberately). `translate_parents.py` avoids the problem for the translation set by dropping parents that contain an `@handle`.
- **No person-name masking anywhere in the text pipeline.** `pii.MASKS` covers email, UPI id, phone and account numbers only; CLAUDE.md rule 5 also names victim names. The OTP/phishing SMS preview used as translation parents carries real-looking names (UPI payers: `from RENU R MAHBUBAN`, `Deposit by transfer from ...`; train-ticket passengers; a delivery rider with a phone number; a doctor; an insurance addressee). `translate_parents.py finalise` drops the 26 parents it found (`NAME_RX`, a list built by reading rare capitalised tokens in context: curated, not exhaustive), so names the reading missed may still be in `translated_final_*.csv`. Not checked: the existing `messages.csv` rows from `uci_sms_spam`, `scam_ham_india`, `india_fraud_final`, `phishing_email` and `fake_job_postings`. Fix: a name mask in `pii.py` (NER or a payer/passenger pattern), run before the `splits-v2` rebuild together with the UPI-handle fix above (it changes text hashes).
- **Template reuse at Jaccard 0.6-0.7 still crosses splits (all sources except `india_fraud_final`).** On the normalised text 992 cross-split pairs sit at 0.6-0.7 (raw: 424); 363 val/test rows (3.3%) have a train twin at >= 0.6 (raw: 280, 2.6%). Mostly `phishing_email` spam and forwarded-reply campaigns (829 pairs; 7.5% of its val/test rows), then `fake_job_postings` (45), `scam_ham_india` (33), `scam_dialogue` (30) and SMS spam. A global 0.6 would catch them; not tried with the current pipeline (company folding already makes the biggest clusters 100-500 rows, and 0.6 will merge more scam/benign job posts).
- **Company grouping only covers job posts with a profile.** `fake_job_postings` has no company-name column; `company_key` is the first 150 chars of `company_profile`. 12,884 of 15,966 posts have one. The 3,082 without are 15.2% fraud (keyed: 1.9%), so about two thirds of the fraud posts are grouped by text similarity only.
- **`india_fraud_final` splits aren't stratified.** It is hash-split per cluster (about 30 clusters per category/label cell), so `job`/benign has 0 test rows (195 train, 5 val) and `utility`/scam has 0 val rows (13 test). Per-category scores on this source skip those cells. Fix: stratify its clusters per (category, label) like `synth_india`.
- **Held-out attack test is thin on real parents.** `messages_adv_test.csv` has 1,865 rows, 749 from real parents: 584 `char_noise`, 124 `url_obfuscate`, only 41 `spaced_keywords`. Report real-parent and all-parent numbers separately (`parent_is_synthetic`). The test uses attacks absent from training, so it can't show recovery on homoglyph / leetspeak / invisible characters; that needs the same attacks on test parents in a separate file. Since 2026-10-09 `url_obfuscate` is also neutralised by `textprep.model_text` (hxxp and `[.]` become `<URL>`), so its recall (0.952 on real parents, equal to the clean parents' 0.960 within noise) reflects the preprocessing, not the model; a link attack that `textprep` does not normalise would be needed to test robustness there.
- **`synth_india` has no val rows, and test (821) is larger than train (756).** Each (category, label) has only two template families, so one goes to test and one to train. Needs a third family per cell (en/hinglish/hi/kn) to fill val.
- **Val and test are lumpy.** Whole company clusters move together: two benign job-post clusters (514 and 108 rows) are 15% of val's benign rows, and val/test hold only 56/98 fraud job posts, so per-source scores on `fake_job_postings` are noisy.
- **`baseline.py` doesn't use `messages_aug.csv` yet** (the homoglyph / leet / zero-width training augmentations).
- **`src/extract_scams.py` never run end to end.** Only the masking and substring-check logic has been tested offline; the Claude call, output CSV and per-page counts are unverified.
- **Multi-line blockquotes are dropped.** A message quoted across several lines with a `>` at the start of each line is not an exact substring of the page after whitespace normalization, so the check rejects it.
- **Victim-name masking depends on the model.** Names are masked only if Claude lists them in `victim_names`; any it misses stay in the text. Spot-check `data/extracted/web_scams.csv`.
- **`--local` may silently truncate long pages.** Ollama's default context window is a few thousand tokens and its OpenAI-style endpoint can't raise it per request, so the start of a long article can be cut off without an error. Start the server with a larger window, e.g. `OLLAMA_CONTEXT_LENGTH=32768 ollama serve`.
- **`--local` never run against a real model.** Ollama wasn't running when it was added; it has only been tested against a mock server.
- **Every run re-processes all pages.** `extract_scams.py` re-calls the API for every saved page and overwrites `web_scams.csv`; there is no per-page cache.
