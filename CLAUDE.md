# CLAUDE.md

Read this at the start of every session. README.md has the full project spec; this file has the working rules.

## Project in one line

Hybrid ML detector for India-specific scams: a text head (fine-tuned multilingual encoder) and a URL head (gradient boosting on lexical features), fused into one calibrated risk score with explanations and tactic tags. VTU Community Project 1BCP308, topic #19.

## Machines

- **Mac (M2 Air, 16GB):** source of truth. All code edits, data pipeline, baselines, URL model, sanity checks, Ollama work (`qwen2.5:7b`, `OLLAMA_CONTEXT_LENGTH=8192`), calibration, explanations, evaluation, frontend. Main env: `.venv`, rebuilt with `pip install -r requirements.txt && pip install -e .`.
- **Kaggle (T4 x2, free tier):** the main fine-tuning GPU (MuRIL, mDeBERTa-v3-base). `notebooks/kaggle_finetune.ipynb` clones the private repo with the `GH_TOKEN` Kaggle secret (read-only, never printed or left in `.git/config`) and runs `src/finetune.py`. Data comes from the **private** Kaggle dataset `scam-shield-data`, mounted under `/kaggle/input/` (since the splits-v2 upload the four CSVs `split_map.csv`, `messages.csv`, `messages_adv_test.csv`, `messages_aug.csv` sit at the dataset **root**, no `final/`; the notebook finds each by name, fails if any is missing or exists twice, and checks the `split_map.csv` SHA-256 before training). T4 is compute capability 7.5, so `--precision auto` picks fp16 with `torch.amp.GradScaler` (bf16 needs >= 8.0). Never edit code there; download the zipped run (no `epoch_*`) and copy it back to the Mac, where all evaluation runs.
- **2nd laptop (RTX 5050, 8GB VRAM, Windows):** set up and usable by hand for fine-tuning (`--precision auto` picks bf16), but no longer the main route; the SSH route is parked. Only `git pull` on it, never edit there. Same outputs as Kaggle, copied back to the Mac.

Start everything with `./run.sh` (frees ports 8000 / 5173, refreshes stale link lists without blocking, runs API + frontend; `--skip-update` / `--force-update`).

## Hard rules

1. **Never train, tune, or look at the final test set** (real messages from real people, collected later). It is evaluated once, at the end.
2. **No leakage.** Splits are grouped (URLs by registered domain; text by near-duplicate `cluster_id`). Augmented rows must come only from parents in the same split. Assert this in code.
3. **Report honestly.** Report per-source, per-language and leave-one-source-out metrics, not just one overall F1. Flag shortcuts (length, language, source, has_ip, has_path, https).
4. **Synthetic and illustrative data never counts as real.** Keep `is_synthetic` and `provenance` (real_circulating / generic_script / illustrative / unknown) accurate. Real-only evaluation excludes everything else.
5. **Mask PII at ingestion** (phone, email, UPI, account/Aadhaar-like numbers, victim names). Only masked text is stored in `data/final/`.
6. **Keys stay in environment variables.** Never write API keys into code, files or commits.
7. **Ask before spending credits.** No Firecrawl research or crawl jobs, and no large paid API runs, without the user's explicit OK. Plain scrapes of listed URLs only.
8. **Never visit a link from a message or a dataset.** Never load its page, connect to its server or IP, or follow its redirects; links are stored and analysed as strings. The app's only outbound calls go through `src/shield/core/net.py` (host allowlist, https, no redirects, ≤ 2 s per call, ≤ 4 s per message): domain-only lookups at the TLD registry (RDAP), Cloudflare DNS-over-HTTPS (the IP is never contacted), crt.sh, and Google Safe Browsing (hash prefixes, only if `SAFE_BROWSING_KEY` is set); and, on the user's button press only, one no-redirect request to a known link shortener. Only a registered domain (or the short link) leaves the machine, never message text. Results stay in memory; domains, URLs and IPs are never logged. List downloads run only in `src/update_link_lists.py`.
9. **Explain changes.** The user wants to understand the pipeline, not just run it. After each change, say what changed, why, and how it affects results. Account for every change in row counts.
10. **Before rerunning downstream steps** (augment, baseline, training), check whether an upstream step is about to change the splits. If so, do that first.
11. **Every text model reads `textprep.model_text(text)`** (`src/textprep.py`): links (including `hxxp` / `[.]` forms and `[Link]` / `[URL]` placeholders) become `<URL>`, then the text is cut to 2000 characters. `baseline.py`, `sanity_checks.py` and the app (`shield.core.router`) use it, and the fine-tuning script on the 2nd laptop must import it (it needs `tldextract`; `git pull` brings `textprep.py`, `url_features.py`, `pii.py`), not re-implement it: a model scored with a different version silently loses accuracy. It is applied at model-input time only. `messages.csv`, `text_hash`, `neardup.py` clustering and `split_map.csv` stay on the raw text, and the URL head is unaffected. `models/text_baseline.joblib` records the token it was trained with and the app refuses an older file (`shield.messages.text_head`).
12. **The real-message test set is TEST ONLY.** `data/real/` (git-ignored) holds the raw exports (Form CSV, SMS Backup & Restore XML, WhatsApp txt), `label_me.csv` (+ `label_me_state.json`: buckets and the group registry), `review_names.csv`, `freeze_manifest.json` and `real_test_v1.csv` (the TEST half of the grouped freeze split; the POOL half is `data/collected/phones/pool.csv`, training material for splits-v3, not guarded); it is made by `src/intake_real.py` and scored once by `src/eval_real.py --final` (every run is one line in `reports/real_eval_ledger.md`; a second run on the same file needs `--again "reason"`). Never train, tune, calibrate or choose a threshold on it, and never read its scores in between. `src/realguard.py` makes `finetune.py`, `calibrate_text_head.py` and `build_text.py` refuse any input under `data/real/` or any row whose text hash is in `real_test_v1.csv` (tests `tests/test_real_intake.py`).

## Which model and effort to use

- **Haiku, low effort:** reruns, quick lookups, small fully-specified edits.
- **Sonnet, medium effort:** most coding steps with a clear spec.
- **Sonnet, high effort:** anything touching splits, leakage, evaluation, calibration, augmentation or GPU training, where a subtle bug silently corrupts results.
- **Opus, high effort:** design decisions, confusing bugs, interpreting sanity-check results, and reviewing another session's work.

| Step | Model | Effort |
|---|---|---|
| Rerun scripts, check counts, read git history | Haiku | Low |
| Near-dup clustering + cluster split | Sonnet | High |
| Sanity checks script | Sonnet | Medium |
| Interpreting sanity results | Opus | High |
| URL head | Sonnet | Medium |
| Rule baseline | Haiku / Sonnet | Low / Medium |
| Zero-shot Ollama baseline | Sonnet | Medium |
| Fine-tuning script (Kaggle / 2nd laptop) | Sonnet | High |
| Calibration + explanations | Sonnet | High |
| Adversarial suite (held-out attack types) | Sonnet | High |
| Fusion model (fit on validation predictions) | Sonnet | Medium |
| Frontend: Gradio prototype, then FastAPI + proper UI | Sonnet | Medium |
| Final review before freezing splits or results | Opus | High |

After any high-effort step, a fresh session should review the diff for leakage and split mistakes.
