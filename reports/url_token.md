# URL token in the text models' input

Generated 2026-10-09 from `src/baseline.py --save` and `src/sanity_checks.py` (before / after) plus one-off counts. Not regenerated by a script.

## What changed

`src/textprep.py` adds `model_text(text, mask_pii=False)`: links become `<URL>`, then the text is cut to 2000 characters (it used to be cut to 2000 raw
characters, so a message with long links now keeps more of its words). It is the input of `baseline.py`, `sanity_checks.py` and `app.py`; the fine-tuning
script must import it too (CLAUDE.md rule 11). What counts as a link: `http(s)://`, defanged `hxxp` / `[.]` / `(.)` / `[://]` forms, `www.`, raw IPs, bare domains with a real
public suffix, and the placeholders `[Link]` `[URL]` `{link}` `<url>`. The URL head and the URL tables are unchanged.

Not touched: `messages.csv` (mtime 7 Oct), `text_hash`, `neardup.py` clusters, `split_map.csv` (SHA-256 `89eec6f1104bc671...`, as in CLAUDE.md), `url_head.md`. All 48,790 rows stay; the
model input changed in **6,299 rows (12.9%)**: train 4,776, val 656, test 867; 6,745 rows contain a link or placeholder in their first 50,000 characters (446 only after
the 2000-character cut, so their input is unchanged). On the changed rows the input is 47 characters shorter on average.

### Guard against sentence boundaries (found by measuring, not assumed)

A first version that accepted any bare `word.tld` matched 17,234 times; **81% (13,900) had a Title-case ending** (`position.You`, `growing.In`, `work.How`): a missing space after a
full stop, where `.you`-style endings and `.in` are real suffixes. `fake_job_postings` alone would have had 6,708 rows rewritten. A bare name with no path is now a link only if its
ending is all lower case (`News.com`, `sf.net`) or the whole name is upper case, and not a source-file ending that is also a country code (`.py .pm .pl .sh .md .rs`). Bare
matches fell to 2,723 (rows with a link in `fake_job_postings`: 6,708 -> 334). Links with a scheme, `www.` or a path are never subject to the guard. Remaining known false positives are few (`p.ms` / `li.ms` / `div.ms` x48 each, `VB.NET` x41, `window.open` x11); a real domain written `Example.Com` would be missed.

### The `[Link]` placeholder

`[Link]` is a template slot in 201 `india_fraud_final` scam rows and no benign row (204 rows in all carry some placeholder; 2 also have a real link). Mapped to `<URL>`
it no longer identifies the template, and `<URL>` presence becomes close to neutral in that source: the share of scam among its rows with a link goes from 0.290 (real links only) to
**0.533** (source base rate 0.500); scam rows with a link 112 -> 313 of 1,600, benign 274 of 1,600. Overall P(scam | row has a link) is 0.364 -> 0.383.
It is not removed everywhere: in `synth_india` rows with a link are 58% scam against 14% benign for every language, so `<URL>` is still a scam cue there (see Kannada below).

## Reading it

- **Overall: no loss.** Test F1 -0.002, real-only unchanged; in-distribution AUROC is flat (changes of at most 0.008) for every source.
- **LOSO AUROC rose where the link carried source style:** `india_fraud_final` +0.028 (PR-AUC +0.072), `scam_ham_india` +0.023, `synth_india` +0.022, `ealvaradob_phishing` +0.013, `uci_sms_spam` +0.006.
  Flat for `phishing_email` (-0.003), `fake_job_postings` (+0.002); `scam_dialogue` -0.010 (PR-AUC -0.016). These fit the idea that links were a shortcut, but one fit per setting cannot show
  which part (real links, defanged links, or `[Link]`) did it; that needs two more runs (`<URL>` without the placeholder mapping, and placeholders only).
- **LOSO F1 moves more than AUROC** because it depends on the 0.5 cut-off: `phishing_email` -0.033 with AUROC flat is a cut-off shift, not a ranking change.
- **Still failing, unchanged in kind:** `phishing_email` and `fake_job_postings` LOSO AUROC 0.587 and 0.570 (near random); `fake_job_postings` scam recall in-distribution 0.194 -> 0.163 (19 -> 16 of 98 scam rows).
- The model is still a TF-IDF smoke test; these numbers say the preprocessing is safe to adopt, not that the text head is good.
