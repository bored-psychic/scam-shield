# gambling_spam and the existing URL head

Generated by `src/gambling_report.py`. The URL head was **not retrained**; this is what the saved host-only head (`models/url_head.joblib`: flag 0.537, Likely scam 0.903) does on the 25,849 new gambling_spam rows, which it never saw. gambling_spam is a category (licensed operators are on both lists), so a flag here is not a defect.

Reference: on benign val + test rows the same head flags 9.1% and reaches Likely scam on 1.2%.

## Shortcuts a retrain would learn (host-only features)

| label | rows | has a subdomain | median host length | has a hyphen | has a digit |
|---|---|---|---|---|---|
| benign | 42,132 | 20.2% | 13 | 6.4% | 5.4% |
| gambling_spam | 25,929 | 0.0% | 16 | 25.4% | 32.6% |
| phishing | 19,757 | 51.5% | 19 | 22.8% | 24.8% |

- **Subdomain depth / `n_labels`:** every gambling_spam row is a bare registered domain (like the Tranco benign rows), while a large share of phishing and ealvaradob-benign rows carry subdomains. A head trained on this would read depth and label count as class cues.
- **TLD:** `.bet` and `.casino` are 12.0% of the new gambling_spam rows and almost absent from every other label (`reports/urls_gambling.md`); `tld_code` is already the head's strongest feature (BUGS.md).
- **Hyphens and digits:** gambling_spam hosts look like phishing hosts on these (compare the rows above; names such as bet365, 1xbet, 777slots), which is why the existing head flags about half of them. A gambling-vs-benign head would partly learn "digits and hyphens".
- **Length:** median host length sits between benign and phishing; check `host_len`, `reg_label_len` and entropy ablations before trusting a new head.
